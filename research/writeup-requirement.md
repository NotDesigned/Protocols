## 理论讲解要求

每个主题的 `writeup/` 是一篇博客式讲解，让没参与研究的人能从头读懂理论，并通过交互动画看到公式在起什么作用。

写作、图表、证据判断和交付前审稿遵循 [Scientific Writing & Editing Protocol](scientific-writing-protocol.md)，以降低 reader cost 和 Figure-first 为原则。本文件补充 HTML 交付、理论讲解和交互动画要求。

### 形式

```text
writeup/
├── index.html     # 单页，直接用浏览器打开
├── data/          # 动画用到的实验数据（从 W&B 导出）
└── scripts/       # 生成 data/ 的脚本
```

- 单个 HTML 文件，离线可打开。公式用 KaTeX，动画用原生 JS / SVG / Canvas，或 D3。
- 依赖固定版本；不依赖需要登录的服务。

### 读者与主线

- 写作前明确目标读者、必需的前置知识，以及全文要回答的一个核心问题。正文开头简短交代知识门槛和读完后能解释、计算或判断什么。
- 选择一个能体现核心问题的最小例子，尽量贯穿直觉、推导、动画和实验对照，让读者在同一个情境中逐步深入。
- 章节围绕核心问题推进。引入新概念时，说明前文遇到了什么困难，以及这个概念如何帮助解决；与主线无关的内容移到补充材料。

### 行文

- 从具体问题或现象切入，按 Motivation → Setting / Method → Results → Conclusion 组织证据链，不要求使用固定的四个章节标题。分析与具体结果逐一对应，并交代结论的局限。
- 先讲直觉再给公式，每个符号首次出现时定义；公式附近用自然语言解释它描述的关系，以及它如何推进当前问题。
- 推导写清关键步骤为什么成立、用了哪些假设，以及结果意味着什么。展开程度以声明的前置知识为准；重复的代数计算可以折叠，关键逻辑不能省略。
- 优先用图和公式表达科学结论，文字补充必要的直觉、定义、条件与推理连接，避免重复描述图上已经清楚的趋势。同一概念保持同一名称。
- 避免紧密的段落和密集的信息量，不同的地方要适当的换行/换段落。保持信息密度适中。
- 分别标明推导结论、实验结论和猜想，并说明适用条件。数值演示用于检查或展示理论预测，实验结果用于提供经验支持，两者都不能替代数学证明。
- 事实、数据和引用应可追溯，不为增加故事感编造经历、对话或细节。删去空泛拔高和没有新增信息的复述，保留理解所需的解释。
- 随研究结论更新，只写当前认识。 

### 交互动画

动画是推导的一部分，不是装饰。每个动画必须：

1. **直接由公式驱动**：画面上的每个量都由正文公式实时计算得出，不预先画好，也不用关键帧近似。
2. **控件就是公式里的符号**：滑块、按钮对应公式中的参数，用同一个符号标注，如 $\eta$、$\beta$、$T$。
3. **公式与画面联动**：显示当前参数代入后的公式数值；关键公式项与画面元素难以对应时，提供双向高亮，帮助读者建立对应关系。
4. **展示关键现象**：让读者通过调参亲眼看到推导预言的现象，如临界值、相变、发散、收敛速度变化。在临界点附近给出提示。
5. **理论对照实验**：适用时，把理论曲线与 `data/` 中的真实实验结果叠加显示，并标注 run id。
6. **提出观察任务**：动画前给出一个具体问题或预测任务，让读者先预测再调参观察；动画后解释所见现象与哪个理论结论相符或不符，以及这次演示能支持的范围。

不合格的例子：
- 动画与公式无计算关系，只是示意图动起来。
- 参数名与公式不一致，读者无法对应。
- 只能播放，不能调节。

### 检查

- 按通用协议完成重要科研图的渲染、视觉检查和数学验证，以及交付前的三次 aggressive editing。
- 各节共同回答开头提出的核心问题，最小例子与正文符号、公式和动画一致。
- 关键推导的操作理由、假设和适用条件清楚；数值演示、实验支持与数学证明没有混用。
- 设置简短的理解检查，并提供答案或解释：让读者用自己的话解释核心机制、预测参数变化的结果，并指出结论失效的条件。
- 打开 `index.html` 无报错，所有动画可交互。
- 每个动画能在正文中找到驱动它的公式。
- `data/` 可由 `scripts/` 重新生成。
