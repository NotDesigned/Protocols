## ML 仓库要求

IMPORTANT: Agents 应当设定 Hooks 在检测到本仓库更新的时候更新此要求。

### 目录结构

目录按实际需要创建；没有对应功能或内容时，无需创建相应目录，也无需保留空目录占位。

```text
project/
├── .gitignore             # Git 忽略规则
├── Docker/                # Docker 相关文件
│   ├── Dockerfile         # 默认镜像
│   └── Dockerfile.xxx     # 按需提供的功能变体
├── pyproject.toml         # 项目配置与依赖定义
├── uv.lock                # 依赖锁文件
├── assets/                # README 的图片等附件
├── configs/               # 实验配置
├── src/                   # 项目源码
│   ├── models/            # 模型结构
│   ├── metrics/           # 指标计算
│   ├── train.py           # 训练入口
│   ├── evaluate.py        # 独立评测入口
│   └── ...                # 其他源码按需组织
├── scripts/               # 独立执行的辅助脚本
├── tests/                 # 核心流程验证
├── data/                  # 数据集
├── pretrained/            # 预训练权重
├── .cache/                # 下载及处理缓存
├── outputs/
│   └── <run>/             # 单次实验
│       ├── checkpoints/   # 训练产生的 checkpoint
│       ├── wandb/         # W&B 本地记录
│       └── ...            # 实验配置、日志与评测结果
└── ...                    # 其他项目文件
```

- `src/metrics/` 实现指标计算并返回结果，由训练／评测流程负责调用、汇总和记录到 W&B。
- `scripts/` 存放独立执行的数据准备、离线切分、结果绘图和批量实验脚本；训练过程中调用的可复用逻辑放在 `src/`。

### 运行环境与目录

- 同时支持镜像运行和本地 uv 环境，推荐镜像，注明验证过的环境版本。
- Docker 相关文件统一放在 `Docker/`，提供可构建并运行项目的 `Dockerfile`；按需提供功能变体，命名为 `Dockerfile.xxx`（如不含评测的 `Dockerfile.train`），注明各版本用途及完整构建、运行命令。
- 统一使用 uv 管理依赖与虚拟环境，提交 `pyproject.toml` 和 `uv.lock`；通过 `uv sync` 同步环境、`uv run` 执行命令。
- 两种运行方式共用依赖定义、锁文件、配置和训练入口。
- 目录遵循下表，支持路径覆盖；容器通过挂载持久化这些目录。本地默认路径相对仓库根目录。

| 用途 | 容器内路径 | 本地默认路径 |
| --- | --- | --- |
| 数据集 | `/workspace/data` | `./data` |
| 预训练权重 | `/workspace/pretrained` | `./pretrained` |
| 实验产物 | `/workspace/outputs` | `./outputs` |
| 下载及处理缓存 | `/workspace/cache` | `./.cache` |

每次实验的配置、日志和评测结果保存在 `outputs/<run>/`，训练产生的 checkpoint 保存在其 `checkpoints/` 子目录。

#### 容器构建

容器本身只作为环境和依赖，不包含代码本身。

代码修改不需要新镜像构建，只需要重新挂载代码即可。也方便在远端云服务运行，挂载云端存储。

### 指标报告

#### W&B 接入

- 统一使用 W&B；已有授权凭证时默认在线记录，无凭证时默认离线记录，不交互式要求登录。
- 支持显式选择 `online`、`offline`、`disabled`，显式设置优先；本地记录保存在 `outputs/<run>/` 下。

#### 指标记录

- 指标按 `train/`、`val/`、`test/`、`optim/`、`perf/`, `eval/` 分组，同名指标保持相同含义、单位和统计口径。
- 默认记录训练损失、当前学习率及实际执行的验证／测试指标；其他指标按任务需要补充。
- 训练指标每隔可配置的 N 步汇总记录，以 `global_step` 为横轴；其含义为优化器更新次数，梯度累积期间不增加。
- `train/loss` 记录窗口平均损失；多 epoch 训练时，每 epoch 结束时另记录整轮平均损失 `train/loss_epoch`，以 `epoch` 为横轴，并附带当前 `global_step`。
- 损失按对应的样本数或有效 token 数加权；评测指标按完整评测集合计算。分布式运行先正确汇总，再由主进程记录。
- 算法、数据集、seed 和消融开关写入 `config`。

### 代码要求

#### 配置与启动

- 训练入口为 `src/train.py`，支持新训练和断点恢复；训练与评测共用配置解析、模型构建和数据处理组件。
- 使用 OmegaConf 管理 `configs/` 下的 YAML 配置，通过 `--config` 指定配置文件，支持 `a.b=c` 覆盖；优先级为命令行覆盖 > 配置文件 > 默认值。
- 启动时拒绝未知配置项和非法值，将最终生效配置保存到 `outputs/<run>/`。

命令格式：

```text
uv run python src/train.py --config <配置文件.yaml> [a.b=c ...]
uv run torchrun <启动器参数> src/train.py --config <配置文件.yaml> [a.b=c ...]
uv run python src/evaluate.py --config <配置文件.yaml> [a.b=c ...]
```

#### 分布式训练

- 多卡训练统一使用 `torchrun`；单卡和多卡共用训练入口与实验参数。启动器参数放在训练入口前，实验参数放在入口后。

### 评测

- 评测入口为 `src/evaluate.py`，支持加载指定 checkpoint 独立评测。
- 汇报格式，在W&B下记录的指标，最终要评测的，也要画出表格。例如比如比较泛化差距 留出NLL loss - 训练 NLL loss。就不要只在最终报告。即使是事后计算补充的，也画进W&B，作为逐（逐若干）step / epoch 来可视化报告。
- 图表通常是折线图，如果有多种子报告，则记录最高最低标准差式。同时用不同图标，例如实心，空心三角形，圆形来代表需要区分的不同配置。

### 文档要求

- 根目录 `README.md` 默认使用英语；如提供简体中文或其他语言版本，在顶部添加语言链接，例如 `[简体中文](README_zh_cn.md)`。
- README 作为统一入口；详细内容按需放入 `docs/` 并链接，论文引用和许可证也应从 README 可达。
- 项目概述：说明用途、对应论文、支持的功能及主要目录职责。
- 快速开始：提供 Docker 和 uv 的完整命令，以及小规模运行示例和预期输出，说明其与完整实验的区别。
- 数据与权重：说明获取方式、预处理、数据格式与划分、存放及挂载位置。
- 运行说明：提供单卡／多卡训练、断点恢复、独立评测和配置覆盖命令，说明 W&B 和本地产物的查看位置。
- 关键配置：说明影响实验含义的参数、默认值和单位，尤其是 batch size、梯度累积和训练长度。
- 结果复现：列出主要实验对应的配置、命令、checkpoint 和预期指标；注明评测口径、硬件与参考耗时，以及未公开部分。
